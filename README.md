# 番茄 · 专注当下

第一版 `v0.1.0`：使用 HTML、CSS 和原生 JavaScript 的番茄时钟，无后端、无第三方依赖。

## 运行

直接用浏览器打开 `index.html` 即可。推荐通过本地 HTTP 服务运行，让浏览器存储的来源保持一致。

```powershell
# 在项目目录执行，需 Node.js 18 或以上版本
npm.cmd start
# 打开 http://127.0.0.1:4187
# 在终端按 Ctrl+C 停止服务
```

不需要执行 `npm install`。Windows PowerShell 使用 `npm.cmd` 可以避开 `npm.ps1` 的脚本执行策略限制，无需修改系统策略；其他系统使用 `npm start`。VS Code 的 Live Server 也可以预览页面。

如果端口被占用，可在 PowerShell 中执行 `$env:PORT = '4188'`，再运行 `npm.cmd start`，并打开对应端口。

## 功能

- 默认专注 25 分钟、短休息 5 分钟。
- 开始、暂停、继续、重置；切换模式时确认是否放弃未完成计时。
- 设置专注 1–180 分钟、休息 1–60 分钟；运行时禁止修改时长，保存会重置当前计时。
- 结束后文字和提示音提醒，自动切换模式，等待用户手动开始下一轮。
- 开始、暂停、重置带有轻量操作音效；“音效开关”统一控制所有声音，关闭后立即静音，刷新后保留选择。
- 点击“试听结束提示音”即可检查声音，无需等待倒计时完成；关闭音效时试听按钮禁用。
- 今日完成番茄数和专注分钟；仅完成的专注计入统计。
- 使用 localStorage 保存计时状态、设置和最多 1000 条完成记录。
- 支持手机、键盘操作和减少动态效果的系统偏好。

## 计时原理

不要依赖定时器执行次数来计算时间。浏览器后台标签页可能降低定时器调用频率。

```javascript
// 开始时保存绝对结束时间
endAt = Date.now() + remainingMs;
// 定时器只负责刷新显示
remainingMs = Math.max(0, endAt - Date.now());
```

暂停时保存剩余毫秒数，继续时重新计算结束时间。刷新后根据保存的结束时间恢复；如果已到期，只记录一次完成，不补跑其他周期。统计归属实际完成的本地日期。

注意：网页关闭或电脑休眠时无法播放提示音；重新打开或恢复页面时校正状态。刷新后声音可能需要点击按钮才能再次解锁，这是浏览器自动播放策略。更改系统时钟会影响剩余时间。

数据只保存在当前浏览器和当前来源，不上传 GitHub，不跨设备同步。清除浏览器数据会丢失记录。建议同时只打开一个计时页面，第一版不协调多个标签页。无痕模式、存储受限或损坏时会显示提示，计时仍可运行。

## 验证

```powershell
# 测试计时精度、暂停继续、刷新恢复、重复完成、设置校验及跨日统计
npm.cmd test
```

人工验收：把专注设为 1 分钟，开始 → 暂停 → 继续 → 刷新 → 完成；确认剩余时间恢复、番茄数加 1、切换为休息并等待手动开始。用手机宽度检查布局，用 Tab 和 Enter 检查按钮。

音效验收：开启音效 → 点击试听 → 开始/暂停/重置 → 关闭开关 → 再操作应保持静音 → 刷新后仍显示已关闭。声音由 Web Audio 合成，无需下载音频文件；浏览器或系统静音时无法听到实际声音。

## GitHub 迭代

首次提交本地第一版：

```powershell
# 检查提交范围
git status
# 仅添加项目文件
git add index.html style.css app.js timer-core.js package.json README.md .gitignore scripts tests .github
git commit -m "feat: 实现番茄时钟第一版"
git push -u origin main
```

后续功能：创建 Issue → 从最新 main 创建功能分支 → 修改与验证 → 推送分支 → 提交 PR → 检查通过后合并。PR 中用 `Closes #编号` 关联任务。

建议下一轮 Issue：增加任务名称、专注记录列表、记录导出；之后引入 Go API 和持久化，再进行容器化、Kubernetes 部署与监控。
